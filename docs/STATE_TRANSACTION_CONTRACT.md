# 상태 트랜잭션과 업데이트 출처

| 항목 | 내용 |
|---|---|
| 문서 유형 | 현재 설계 계약 |
| 상태 | 합의 및 구현된 보호 규칙 |
| 기준 | [2026-10-31 고정 기준선](BASELINE.md) |
| 적용 범위 | 협조형 Core·CLI·UI·안전한 파일 편집 |

## 의미와 출처

- 각 세션이 자신이 기여하는 태스크에서 무엇을 추적할지 정의한다. 하나의 항목을 여러 세션이 갱신할 수 있다.
- 항목 ID·revision·생성/마지막 작성 세션·시각·report ID·근거를 보존한다. 예전 작성자는 이력에 남는다.
- 최신값은 마지막으로 커밋에 성공한 유효 업데이트다. 의미적 충돌은 작업 세션이 다시 읽고 판단한다.
- 출처 필드와 유효한 스키마는 실제 작성자 인증이나 내용의 진실성 증명이 아니다. 외부 직접 편집을 옛 세션의 보고로 묵인하지 않는다.

## 읽기 → 판단 → 조건부 커밋

1. CLI가 일관된 현재 상태·revision·작성 세션을 반환한다.
2. 에이전트는 **락 없이** 판단한다. 다른 세션이 이 동안 보고할 수 있다.
3. 제출한 expected revision을 짧은 공통 flock 안에서 비교한다.
4. 일치하면 스키마·범위·핀·중복 검사 후 값·출처·이력·영수증을 함께 커밋한다.
5. 불일치하면 쓰지 않고 `revision_conflict`와 최신 상태를 돌려준다. 오래된 보고를 자동 강제 적용하지 않는다.

현재 검증 단위는 태스크 revision이다. 항목 revision과 출처도 유지한다. 관측 DB의 수집 시각과 [사용자 확인 위치](UI_READ_CURSOR_CONTRACT.md)는 태스크 revision을 올리지 않는다. 표준 스킬은 충돌 후 재판단·재제출을 최대 2회로 제한하고 계속 실패하면 미반영을 드러내며 원래 작업을 계속한다.

## 인간 정보 보호

추적값은 명시적으로 고정한 경우에만 자동 갱신에서 보호한다. 사람이 수정한 비고정값은 후속 유효 보고가 갱신할 수 있고 이전 수정은 이력에 보존한다. Core는 고정된 기존 항목의 변경·보관과 보고를 통한 핀 해제를 거절한다. 새 ID로 의미상 대체하는 우회는 스킬에서 금지하며, Core가 의미 중복을 자동 판별하지는 않는다. 메모·자유 View·사용자 확인 위치는 에이전트 보고의 갱신 대상 밖이다.

추적 중단은 보관 상태로 다뤄 이력을 남긴다. 같은 제목만으로 항목을 합치지 않는다. 태스크 완료/관측 OFF는 새 보고 반영을 거절하며 기존 영수증 재생은 원래 성공 결과를 반환한다. 공유 세션의 전역 수집은 다른 태스크를 위해 계속된다.

## 파일 커밋과 복구

교체되는 state.json 자체가 아닌 안정적인 `.lock`을 사용한다. 협력하는 읽기·쓰기 모두 동일 경계를 따른다. 락 대기는 유한하며 `busy` 오류를 반환한다. 단일 파일은 임시 저장·fsync·원자적 교체를 사용한다.

여러 태스크/이력/영수증 갱신은 작은 prepared journal로 기록하고 읽기·쓰기 전에 복구한다. 실패·중단으로 결과가 불확실하면 같은 report ID로 재시도한다. 같은 보고의 재생은 revision을 올리지 않는다. 규약 밖 수정이 미완료 커밋과 충돌하면 원문을 조용히 덮어쓰지 않는다.

손상 범위를 판별할 수 있으면 해당 태스크의 last_good/오류를 보존하며 다른 정상 태스크를 제공한다. journal 자체가 모호해 영향 범위를 알 수 없으면 저장소 접근을 중단한다. 원문과 정상 이력이 없는 경우 빈 정상 상태를 꾸며내지 않는다.

## 직접 편집·이관

`edit-export → validate → edit-apply`가 안전한 편집 경로다. 편집 시간에는 락을 점유하지 않고 반영 시 expected revision을 검사한다. 직접 원본 파일 수정은 허용하되 정상 커밋으로 자동 인정하지 않는다. 명시적 복구도 관측한 digest를 검사하고 원문을 보존한다.

이전된 root의 `.relocated.json`은 기존 `.lock`을 얻은 뒤 검사한다. 이미 만들어진 인스턴스와 대기 writer도 새 위치 안내로 중단한다. marker 손상·심볼릭 경로도 조용히 통과하지 않는다. 임의의 직접 writer·전원 장애 전부를 완전히 통제하는 파일 DB나 보안 경계는 아니다.
