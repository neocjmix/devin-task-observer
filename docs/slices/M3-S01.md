## 이번 범위

- 기존 Python 진입점을 확장한 에이전트용 CLI. 명시적 세션 등록·조회, 태스크 생성·조회·연결, 보고 시작·중단을 제공한다.
- 세션이 기존 항목을 읽고 재사용하거나 안정적인 ID로 새 항목을 정의한다. 추적 중단은 보관으로 표현하고 이력을 남긴다.
- 태스크 상태·연결·추적 정의·항목 값·작성 출처·보고 이력을 버전 스키마가 있는 파일로 저장한다. 기존 DB의 장식용 export가 아니다.
- 읽기 시 revision, 쓰기 시 expected revision을 검사한다. 판단 중에는 락을 잡지 않고 최종 비교·반영만 짧은 내부 락으로 묶는다.
- 값·updated-by·revision·이력·report ID의 원자적 반영, 중복 재전송, 중단 후 복구를 검증한다.
- 인간이 고정한 추적값만 에이전트 변경에서 보호한다. 비고정 인간 수정은 갱신 가능하되 이력을 보존한다. 메모·확인 위치는 보고의 수정 대상이 아니다.
- 안전한 작업 사본 편집·검증·조건부 반영을 제공한다. 규약 밖 직접 수정·잘못된 스키마는 원문을 보존하고 진단하며 정상 태스크는 계속 조회한다.
- 기존 수집 저장소의 결정론적 관측을 읽기 전용으로 연결한다. 관측된 사실과 세션이 보고한 값을 구분한다.
- 스킬 참조는 CLI 사용·항목 조회·변경 보고·충돌 재판단 최대 2회·보고 중단을 설명한다. 기본 경로에 모델 호출은 없다.

## 제외 범위와 보존 경계

- 메뉴 막대 UI와 훅 설치·세션 ID 자동 전달의 실제 호환성은 다음 슬라이스에서 검증한다. 이번 CLI 검증이 메뉴 UI 완료를 뜻하지 않는다.
- 기존 SQLite 태스크·인간 View·메모·핀·체크포인트를 자동 변환하거나 덮어쓰지 않는다. 새 태스크와 기존 태스크의 저장 경계를 명시한다.
- 기존 M2 독립 분석 경로는 유지한다. 이번 작업에서 기능 확대·모델 실행·회사 환경 검증을 하지 않는다.
- 실제 진행 중인 Devin 세션에 프롬프트를 보내거나 제어권을 획득하지 않는다. 개인 합성 테스트만 사용한다.
- 보고 ON은 에이전트를 깨우거나 매 턴 보고를 강제하지 않는다. 자발적 보고 품질과 전체 비용 절감은 CLI 테스트만으로 입증되지 않는다.
- 임의 외부 프로세스가 규약 없이 원본 파일을 바꾸는 행동까지 원자적 트랜잭션으로 보장하지 않는다. 오류·불확실성을 숨기지 않는다.

### 동시성과 복구 증거

- 서로 다른 실제 Python 프로세스가 같은 revision을 읽고 동시에 보고: 하나만 커밋, 다른 하나는 revision_conflict. 판단 중 락을 잡지 않는다.
- 두 태스크 반영 중 첫 state.json 교체 직후 `os._exit(77)`: 원시 파일은 일시적으로 서로 다른 revision이지만 다음 협조형 읽기 전에 journal을 복구해 두 태스크 모두 같은 커밋 결과로 읽었다.
- 성공 receipt 저장 후 응답 전 `os._exit(78)`: 같은 보고 재전송은 원래 receipt를 재사용하고 revision을 추가하지 않았다.
- 중단 커밋과 외부 raw 편집 충돌: 영향 태스크는 unavailable/last_good로 표시하고 원문을 보존; 무관한 태스크는 조회·갱신 가능.
- 손상 파일·미지원 스키마·잘못된 task ID·symlink/hardlink·누락 원본·복구 중 digest 변경을 거절하거나 격리했다. 명시적 복구는 원문 백업 후 마지막 정상 커밋을 복원한다.

### 보고 흐름 증거

독립적인 검증 에이전트가 동봉 스킬을 읽고 격리된 합성 프로젝트에서 실제 CLI를 사용했다. A의 `render(value)` 테스트는 성공했고 B가 새 `compact` 인자를 사용하는 테스트는 TypeError로 실패했다. 이것은 의도적으로 만든 작업 문제이며 Observer 테스트 실패가 아니다.

| 최종 항목 | 표시 상태 | 마지막 업데이트 |
|---|---|---|
| 구현 | revision_needed | 합성 세션 A가 B의 실패를 읽고 재판단 |
| 테스트 | failed | 합성 세션 B |
| 인터페이스 블로커 | blocked | 합성 세션 B |
| 수정 후 재검증 | pending | 합성 세션 B |
| API 결정 | decision, pinned | 명시적 인간 고정 경로 |

최종 태스크 revision은 9, 항목은 5개였다. 인간 메모·핀을 보존하고 오래된 A 보고는 revision_conflict, 핀 우회는 pinned_item으로 거절했다. 근거는 합성 테스트 파일·출력 참조이며 독립 검증된 제품 완료로 승격하지 않는다. 원본 합성 작업 파일과 실행 출력은 임시 경로에만 두었고 저장소에는 넣지 않았다.

기존 관측 연결 테스트는 허용 workspace와 태스크 연결을 적용하고 현재 source hash의 후보·계획만 읽었다. 읽기 전후 기존 Observer DB와 합성 Devin source 파일 바이트, 보고 상태가 동일했다. 수집 저장소가 없으면 경고하고 새 DB를 생성하지 않았다.

### 구현 파일과 제한

- `observer/cooperative.py`: 태스크·세션·항목 정의/보고·보호 정책. 의미 조정은 세션의 판단에 맡긴다.
- `observer/file_store.py`: 파일 원본·짧은 커밋 락·revision 비교·journal·history·receipt·복구.
- `observer/state_cli.py`, `state_schema.py`, `schemas/cooperative-v1/`: CLI·입력 한도·자체 검증·게시 스키마. 성공 receipt와 list는 전체 View를 반복 출력하지 않는다.
- `observer/state_observations.py`: 기존 수집기의 읽기 전용 연결. SQL 태스크·View나 수집기를 새 파일 상태로 자동 이관하지 않는다.
- `skills/observer-reporting/SKILL.md`: 저장소에 동봉한 보고 지침. 실제 Devin 자동 발견·세션 ID 전달·훅 설치는 수행하지 않았다.

상태 파일당 최대 2 MiB, 보고 최대 20개 태스크/태스크당 100개 연산을 지원한다. 전체 스냅샷 history/receipt는 계속 커지며 장기 규모 검증과 보관 정책은 남아 있다. 일반 읽기는 최신 JSON만 파싱하지만 이력 파일 이름 목록은 검사한다. 손상 journal에서 영향 범위를 판별할 수 없으면 저장소 전체를 보수적으로 중단한다. 협조하지 않는 임의 파일 쓰기와 하드웨어 전원 차단의 원자성까지 증명하지 않았다.

세션 ID 등록은 명시적 주장이지 인증이 아니다. 근거 참조의 실제 존재·내용 진실성은 자동 검증하지 않는다. 보고 ON은 에이전트를 깨우거나 스킬을 주입하지 않는다. 모델을 이용한 분석은 호출하지 않았으며 기존 실제 모델 통합 테스트 두 개는 이번 결과에서 제외했다.
