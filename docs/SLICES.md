# 구현 슬라이스와 기준선

2026-10-30. 사용자가 저장소 점검·문서 정합성 정리 후 다음 슬라이스의 구현과 검증을 승인했다.
새 협조형 보고 설계는 이제 구현 단계다. 기능별 완료 여부는 아래 슬라이스의 실제 증거로 판단한다.

## 문서의 우선순위

1. [설계 변경안의 사용자 확정](DESIGN_CHANGE_PROPOSAL_2026-10-30_KO.md#0-사용자-후속-확정--이번-결정이-우선)과 [상태 트랜잭션 계약](STATE_TRANSACTION_CONTRACT_2026-10-30_KO.md)이 새 구현의 제품·보호 규칙이다.
2. 이 목록과 개별 슬라이스 문서가 이번 구현 범위·상태·검증 결과를 정한다.
3. [구현 계획](IMPLEMENTATION_PLAN.md), [데이터 계약](DATA_AND_RECONCILIATION.md), [검증·인수인계](VALIDATION_AND_HANDOFF.md)의 P0~M2 본문은 기존 런타임의 설계와 증거다. 새 협조형 보고 방향과 충돌하는 옛 규칙을 새 기능에 적용하지 않는다.
4. P0~M2 진행 문서와 날짜가 붙은 평가 문서는 당시 구현·실험 기록이다. 과거 실험의 성공을 새 저장·CLI·스킬 경로의 검증으로 간주하지 않는다.

예를 들어 M2의 별도 모델 분석, 인간이 수정한 모든 값의 영구 보호, 미확정 의미 변경의 사용자 승인은
기존 M2 경로의 규칙이다. 새 보고 경로는 세션의 판단, 최신 유효 커밋, 명시적 고정값 보호,
충돌 시 세션 재판단을 따른다. 메모와 이력은 두 경로 모두 보존한다.

## ID 컨벤션

기존 저장소는 P0~P4와 M1/M2 마일스톤 및 `*_PROGRESS.md`를 사용했고 개별 슬라이스 ID 규칙은 없었다.
후속 마일스톤을 **M3 — Cooperative Task Tracking**으로, 첫 구현 단위를 **M3-S01**로 정한다.
이후 ID는 같은 마일스톤 안에서 `M3-S02`, `M3-S03`처럼 증가한다. 기록은 `docs/slices/<ID>.md`에 둔다.
각 기록에는 시작 기준선, 범위·제외 범위, 수용 시나리오, 실제 검증과 남은 제약을 남긴다.
커밋 제목에는 해당 ID를 붙인다. 테스트 개수만으로 제품 전체 완료를 선언하지 않는다.

## 현재 목록

| ID | 범위 | 상태 |
|---|---|---|
| [M3-S01](slices/M3-S01.md) | 새 태스크의 파일 원본 상태, 협조형 보고 CLI, 낙관적 커밋·복구·검증, 스킬 참조, 기존 결정론적 관측의 읽기 연결 | 완료: 208개 실행·206 통과·실제 모델 2 skip; 전체 제품 완료는 아님 |
| [M3-S02](slices/M3-S02.md) | 메뉴 막대·독립 수집 실행; 실제 세션 식별·스킬·훅 보고 | 구현 완료: 실제 Desktop/CLI 보고·충돌·핀 보호 확인; 메뉴 객체 검증, GUI 클릭 제한 별도 기록 |
| [M3-S03](slices/M3-S03.md) | 기존 SQLite 태스크·View 보존 이관·복원·일상 실행 | 구현 완료: 합성 보존·백업·복원 및 실제 CLI 검증; 기존 사용자 DB 자동 전환 없음 |

M3-S01에서 새 태스크 상태는 파일을 원본으로 삼는다. 기존 SQLite 태스크·메모·View와
수집 체크포인트는 그대로 남고, 새 저장소로 자동 이관하거나 두 원본을 동시에 갱신하지 않는다.
실제 스킬의 후속 능동보고와 네이티브 메뉴 객체·지속 수집을 확인했다. 메뉴 드롭다운 클릭, 긴 대화의 압축 후 이행, 장기간 보고 정확도는 검증 범위 밖이다. 전체 결과는 [M3 진행 기록](M3_PROGRESS.md)에 구분한다.

## 시작 기준선과 기존 문제

- 시작 브랜치: `p0/desktop-probe`; 기존 Draft PR #1을 계속 사용하고 자동 머지하지 않는다.
- 시작 HEAD: `d80f22b7cf53f0551aec6f5fedb260f8d8ee9926`. 기존 런타임 구현 기준은 `f20696de11cbbe833a84c80bb9ad25c286021104`이며 그 뒤에는 설계 문서만 추가됐다.
- 시작 시 미커밋 문서는 `docs/M2_PROGRESS.md`의 후속 점검 링크와 `docs/DESIGN_GAP_AUDIT.md`였다. 두 파일은 f20696d의 합성 경계 점검 기록이며 새 슬라이스의 테스트 결과가 아니다. 원문은 보존했고 기준선 문서 커밋 `747cc6c`에 반영했다.
- 기존 M2 감사에서 지적한 원본 공백 이후 재개, 혼합 출처 상태 변경, 연결 범위 변경 시 신선도, 보류 status의 UI 처리와 의미 재서술 중복 한계는 기존 경로의 미해결 사항이다. 새 경로 도입으로 고쳐졌다고 보지 않는다.
- 새 슬라이스의 시작 테스트·최종 테스트 결과는 [M3-S01](slices/M3-S01.md)에 기록한다. 실제 모델 테스트의 skip과 합성 실행을 구분한다.
