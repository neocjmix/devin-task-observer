## 작성 규칙

문서는 현재 구현과 계약을 직접 설명한다. 기능이 바뀌면 해당 문서를 고치며 변경 내용을 별도 과거 문서나 안내문으로 쌓지 않는다. 수행할 일은 백로그와 이슈에만 기록한다. 한 문서의 내용을 다른 문서에 중복 저장하지 않는다.

H1 하나와 `문서 유형 / 상태 / 기준 / 적용 범위` 표로 시작한다. 한국어 설명과 정확한 코드·CLI 식별자를 사용한다. 기능 설명은 범위·구현·검증·제약을 구분하며, 실제·합성·Mock·미검증을 섞지 않는다. 날짜는 KST다.

기준 코드와 검증 결과는 [BASELINE](BASELINE.md)에 관리한다. 합의한 보호 규칙은 데이터·트랜잭션 계약, 다음 일의 상세 완료 조건은 GitHub 이슈에 둔다. 구현 시 현재 문서·백로그·이슈를 함께 갱신하고 실제 조건을 충족한 이슈만 닫는다.

`skills/`는 에이전트 실행 지침, `schemas/`는 데이터 검증 정의다. 이 두 곳도 현재 동작과 일치하도록 유지한다. 개인정보·원본 대화·DB·인증정보·개인 스크린샷은 문서에 넣지 않는다.

## 점검

`python3 scripts/check_docs.py`로 상대 링크·제목 앵커를 검사하고 `git diff --check`를 실행한다. 링크 검사와 별도로 코드·스키마·명령·이슈가 설명과 일치하는지 확인한다.
