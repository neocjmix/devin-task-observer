## 범위와 수용 기준

1. 선택한 개인 작업 공간에 스킬과 최소 lifecycle hook을 명시적으로 설치·조회·제거한다. 기존 훅은 보존하고 소유한 파일이 변경되면 무리하게 덮어쓰지 않는다.
2. 시작 훅에서 실제 session ID와 CLI/context 경로를 전달한다. 세션은 태스크를 확인하고 연결·보고 ON/OFF·추적 정의·조건부 보고를 수행한다. 훅은 보고를 생성하거나 원래 작업을 차단하지 않는다.
3. 합성 새 Devin Desktop 세션에서 시작 후 후속 변경을 보고하는지 확인한다. resume/compaction은 지원 증거와 합성 테스트를 구분한다. ON 표시를 보고 충실도 보증으로 설명하지 않는다.
4. Python 메뉴 막대에서 수집 상태·마지막 성공·태스크 항목·업데이트 세션·보고 ON/OFF·오류를 조회한다. UI는 브라우저를 열지 않는다. 기본 관측·조회에는 모델을 호출하지 않는다.
5. 별도 수집 프로세스가 재시도·중복 실행 차단·안전 종료를 제공한다. 선택적 Cocoa bridge는 외부 Python 환경에 설치하며 앱은 얇은 실행 진입점만 갖는다.

기존 사용자 세션에 프롬프트를 보내지 않는다. 테스트는 새 개인 합성 세션에서만 한다. 전역 훅, blanket 도구 허용, Electron, Swift 제품 로직, M2 모델 확장은 제외한다.

## 검증 기록

구현과 아래 개인 합성 수용 검증을 완료했다. 테스트용 데이터와 런타임 산출물은 저장소 밖에 둔다.

- 기준선 208개 → 최종 전체 268개 실행, 266 통과·실제 M2 모델 opt-in 2 skip·실패 0. 이 별도 실제 M3 세션 실험은 unittest의 live model skip과 다른 경로다.
- 실제 Desktop 3000.10.67 Local에서 새 개인 합성 세션을 만들었다. `SessionStart`의 실제 ID context 전달, 스킬 호출, `whoami` 확인, 태스크 연결·ON을 확인했다. 최초 스킬의 연결/revision 안내 부족은 구체 순서와 자체 완결 참조로 수정했다.
- 첫 Desktop 세션이 합성 `parse_count` 구현과 unittest 2개를 작성·실행하여 통과했다. 구현·테스트 작성·실행 결과 3개 항목을 직접 CLI로 보고했다. 중간 인간 메모로 stale revision 보고가 거절된 뒤 세션이 재조회·재제출하여 성공했고 메모는 보존됐다.
- Desktop 기본 모드의 CLI 실행에는 승인 단계가 있었다. 테스트 담당 에이전트가 해당 합성 명령만 승인했다. 이를 무인 권한 획득 성공으로 설명하지 않는다. 스킬 설치는 도구 권한을 자동 허용하지 않는다.
- 메뉴·네이티브 객체·패키징·지속 수집 결과는 [별도 기록](M3-S02_MENU.md)에 있다. 최초 CUA에서는 창 없는 앱 연결이 실패했으나, 사용자 권한 승인·인증 후 AppleScript로 아이콘·태스크·항목·세션 메뉴를 클릭하고 실제 화면을 캡처했다. 수동 새로고침의 수집 재개와 상태 파일 불변도 확인했다.
- 임시 launchd collector를 실제 bootstrap하고 SIGTERM 이후 다른 PID로 자동 재시작을 확인한 뒤 bootout했다. 영구 자동 실행은 등록하지 않았다.

- 같은 Desktop 세션에 보고를 언급하지 않고 파서 요구 변경만 전달했다. 세션이 3개 테스트를 실제 통과시킨 후 능동적으로 태스크를 읽고 보고했다. 그 사이 B의 보고로 revision이 바뀌어 거절됐고, 재조회 후 고정 항목 갱신도 거절됐다. 세션이 핀 항목을 제외한 보고로 revision 13에 커밋했고 메모·핀·기존 이력은 보존됐다.
- 별도 실제 CLI 세션 B는 A의 초기 구현 복사본에서 underscore 입력 거절 테스트를 실행해 실제 실패를 확인하고 실패 사실·블로커·다음 행동 3개를 보고했다. A는 이후 B가 쓴 블로커와 다음 행동을 자신의 수정 결과로 갱신했다. 항목의 최신 작성자는 A, 이전 값과 B 작성자는 이력에 남는다.
- B의 앞선 비대화형 실행 2회는 샌드박스/도구 승인 경계로 실패했다. 종료 코드 0만으로 성공 처리하지 않았다. 정상 대화형 권한 승인으로 합성 파일 2개만 허용한 세 번째 실행에서 실제 테스트와 보고를 완료했다. 보호 모드를 끄거나 전역 권한을 열지 않았다.

- 같은 Desktop 세션에 스킬로 보고 중단을 요청했다. 최신 revision을 읽고 본인 기여만 OFF로 커밋한 뒤 재조회했다(revision 14). 다른 세션의 ON, 항목 6개, 메모 1개, 고정 항목, 이력 14개는 보존됐다.

- 실제 보고가 쌓인 메뉴 앱을 SIGTERM으로 종료 후 다시 실행했다. 수집이 성공하고 revision 14의 상태 파일 해시, 항목 6개·메모 1개가 동일함을 확인했다.

## 보고 정확성의 실제 한계

Core는 의미를 판정하지 않는다. B는 실패를 발견한 검증 항목에 `completed`(검증 수행 완료)를 사용했고, 별도 blocker는 `blocked`로 보고했다. A는 `isdigit()`으로 비-ASCII 숫자까지 거절했다고 보고했지만 독립 실행에서 전각 숫자 `１２`는 여전히 12로 변환됐다. 그러므로 **능동보고·저장 경로는 검증됐고 합성 파서 요구의 완전한 충족은 검증되지 않았다.** 이 사례를 성공한 구현으로 포장하지 않는다.

B는 초기 복사본, A는 수정한 작업 공간을 사용했다. 최신 유효 보고를 채택하는 합의대로 A의 판단이 현재값이 됐지만, 다른 복사본까지 고쳐졌거나 재검증됐다는 뜻은 아니다. `reported`, 작성 세션, 근거, 이력을 함께 읽어야 한다. 일부 파일 근거는 세션이 제시한 문자열로, Core가 존재·내용을 자동 증명하지 않는다.

전체 실행 결과·토큰·증거 위치·남은 한계는 [M3 진행 기록](../M3_PROGRESS.md)에 있다. 장기간 보고 누락률과 실제 긴 대화 압축 후 이행은 완료로 주장하지 않는다. 실제 메뉴 클릭·캡처는 후속 검증 기록에 한정한다.
