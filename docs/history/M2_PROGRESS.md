# M2 — Semantic Task Tracking

| 항목 | 내용 |
|---|---|
| 문서 유형 | 과거 계획·결정·검증 기록 |
| 상태 | 보존; 현재 지시나 미완료 목록이 아님 |

> 현재 구현은 [기준선](../BASELINE.md), 남은 작업은 [백로그](../BACKLOG.md)를 따른다. 본문의 현재·다음·미구현은 당시 시점의 표현이며, 완료나 미검증 판정을 소급 변경하지 않았다.

2026-10-29. 기존 `p0/desktop-probe`, Draft PR #1과 M1을 이어 구현했다. 개인 환경에서 **두 실제 Devin Desktop 합성 세션 → 수동 Semantic Refresh → 실제 Codex CLI → 검증된 패치 → 지속 상태와 브라우저**의 수직 슬라이스를 실행했다. 개인 계정의 실제 Devin ACP에서도 독립 세션·스트리밍·두 합성 세션의 패치 적용을 확인했다. 사내 ACP 운영 승인과 실제 업무 유용성 검증은 완료되지 않았다. 이 문서의 실제 데이터는 모두 격리된 합성 세션이며 회사 자료는 사용하지 않았다.

## 사용자가 얻는 것

태스크를 만들고 세션을 연결한 뒤 Semantic Refresh를 누르면 새 자연어 기록에서 진행, 블로커, 결정, 질문, 다음 행동, 발견, 가설을 추출한다. 결과는 태스크별 기계 관리 영역에 자동 반영된다. 인간 메모나 고정 항목을 매번 다시 입력하거나 일반적인 안전한 갱신을 일일이 승인할 필요는 없다.

새 이벤트 수집과 의미 분석은 별개다. **이번 버전의 의미 분석은 수동 요청만** 실행한다. 수집·일반 Refresh·대시보드 조회는 모델을 호출하지 않는다. 의미 분석을 하지 않았거나 실패하면 대기 관측, 마지막 반영 시각과 오류를 보여준다. 원본의 보고를 실제 완료나 외부에서 확인된 사실로 승격하지 않는다.

## 구현 경로

- `observer/model_adapters.py`: `SemanticModelAdapter.analyze(bundle, cancel)`와 두 실행 어댑터. 공통 `ModelResult`는 proposal, usage, provider_run_id, diagnostics를 반환한다. 모델 어댑터는 태스크 DB나 View를 수정하지 않는다.
- `observer/reconciliation.py`: 태스크별 의미 커서, 선택된 증분, 관련 기존 항목, 검증·적용·사용량·실행 이력. 기존 수집 체크포인트와 독립적이다.
- 기존 `tasks`, `contributions`, `task_views`, 인간 작성 항목을 재사용한다. 작은 별도 `tracking_*` 테이블에 기계 관리 항목·이력·실행·의미 커서·처리 키·승인 대기 변경을 저장한다. 범용 플러그인/워크플로 프레임워크를 추가하지 않았다.
- 기존 서버에 `/api/semantic/refresh`, `/api/semantic/item`, `/api/semantic/proposal`을 연결했다. `/api/task-observer`는 저장된 의미 상태도 반환한다. 브라우저 입력 영역은 자동 상태 갱신과 분리했다.

### 증분과 입력 선택

1. 활성 태스크–세션 연결과 작업 공간 허용 목록으로 대상을 한정한다. 태스크별/세션별 의미 커서 이후의 관측만 선택한다. 리뷰 확인 위치는 바꾸지 않는다.
2. 관측된 user/assistant/tool-result 텍스트와 알려진 `todo_write` 형식을 선택한다. 사용자 첫 입력의 `chisel/acp-content-blocks`가 관측된 형식이면 text 블록만 사용하고 주입된 resource 컨텍스트는 제외한다. 이 블록이 없는 관측된 일반 content는 출처 역할과 함께 전달한다. 모든 입력은 지시가 아닌 신뢰할 수 없는 자료로 취급한다.
3. 같은 세션/메시지 ID/선택된 텍스트 해시는 재해석하지 않는다. 계획과 리소스 구문은 결정론적으로 먼저 추출한다. 지원하지 않는 일반 대화 노드는 제외 이유를 저장하고 의미 신선도를 `partial`로 표시한다. 시스템 노드 제외와 중복은 별도로 구분한다.
4. 새 증분의 단어, 출처 세션, 아직 열린 항목을 이용해 관련 기계 항목을 최대 24개/10KB 선택한다. 관련 인간 항목은 별도 최대 4KB이며 수정 권한이 없다. 전체 View나 전체 트랜스크립트를 매번 보내지 않는다. 관련성 선택은 휴리스틱이므로 먼 문맥을 놓칠 수 있다.
5. 프롬프트 전체 48,000 UTF-8 bytes, 선택된 새 텍스트 24,000 bytes, 단일 이벤트 16,000 bytes, 새로운 자연어 처리 최대 40개로 제한한다. 큰 이벤트를 몰래 자르지 않고 명시적으로 실패하며 의미 커서를 보존한다. 다음 배치가 있으면 대기 상태를 유지한다.

## 패치와 상태의 권한

버전 1 JSON 패치는 add, update_status, attach_evidence, supersede, flag_conflict, propose_section을 지원한다. 입력의 수정 가능한 기계 항목 ID만 target_id로 허용하도록 실행별 JSON Schema를 제한한다. 수정 대상이 없으면 add/propose_section과 null target만 안내한다. 공통 JSON Schema와 별도로 Core가 태스크 ID, 예상 기계 상태 revision, 인간 View revision, 연결/범위, 대상 ID, 새 근거 ID, 크기, 중복, 소유권과 고정을 검증한다. 같은 패치의 새 항목 key를 참조하는 충돌도 해석한다. 실재하지 않는 ID는 거부한다.

- 안전한 추가와 근거 연결은 자동 적용한다. 상태 변경은 기존 기계 항목에 대해 **동일 세션의 증명 가능한 후속 연결**이 있고 기존 충돌이 없을 때만 자동 적용한다. 글로벌 타임스탬프로 승자를 정하지 않는다.
- 동일 출처가 명확하게 수정한 기계 주장에는 비파괴 superseded 상태를 적용할 수 있다. 이전 본문과 이력은 남는다. 출처가 다르거나 혼합됐거나 순서가 불명확하면 승인 대기다.
- 상충하는 주장은 양쪽을 보존하고 연결한다. 인간 결정과 충돌하는 새 기계 주장에는 인간 항목 참조를 달 수 있지만 인간 본문·상태·핀은 변경하지 않는다. 충돌 해결을 모델이 단독 확정하지 않는다.
- 새 사용자 View 섹션은 제안으로 저장하고 승인 전 만들지 않는다. 보호된 항목 변경이나 기존 key와 다른 내용의 추가도 자동 덮어쓰지 않는다.
- 사용자가 기계 항목을 수정하거나 고정하면 인간 소유로 전환되어 이후 모델이 덮어쓸 수 없다. 원래 인간 View와 기계 상태는 계속 별도로 유지한다.
- 모델 해석의 epistemic 값은 reported/hypothesis다. `verified`를 모델이 설정할 수 없다. 완료 보고, 해결 보고와 실제 검증은 다르다.
- 모델 실행 뒤 원본 해시와 연결/뷰 버전을 다시 검사한다. 항목·이력·처리 키·의미 커서는 하나의 트랜잭션에서 커밋한다. 빈 결과도 durable no-change 실행으로 기록한 뒤에만 진행한다.
- 실패·거부된 실행은 예약 예산과 가능한 사용량·제안을 보존하고 그 실패 실행으로 커서를 진행하지 않는다. 형식·대상 ID·권한 형식 오류에는 같은 수동 요청 안에서 허용 대상을 명시한 보정 요청을 최대 1회 한다. 첫 거부 실행도 예약·사용량·오류를 남기고 보정 호출 역시 한도를 검사한다. 네트워크/인증/타임아웃/출처/동시 수정 오류는 자동 재시도하지 않는다. 남은 실패는 명시적 재시도가 필요하며 같은 태스크·증분·revision·모델 입력 키당 총 3회를 넘기지 않는다. format_repair=false로 이 보정도 끌 수 있다. 관측 수집 자체는 계속된다.

## CodexExecAdapter — 실제 검증

**CLI는 Observer에 번들하거나 복사하지 않으며 자동 다운로드하지 않는다.** 설정에 명시된 기존 외부 실행 파일을 호출한다. 이 Mac에서 실제 사용한 파일은 공식 ChatGPT 앱 안의 CLI이며 버전은 `0.163.0-alpha.11.2`다. 파일의 `codesign --verify --strict`가 성공했다. 이 앱 내부 경로는 이 검증 환경의 설정일 뿐 제품 기본 경로나 안정된 배포 API로 가정하지 않는다.

설치된 `exec --help`와 `features list`를 확인했다. 비대화형 `exec`, stdin 입력, `--json`, `--output-schema`, `--output-last-message`, `--ephemeral`, `--sandbox read-only`, `--ignore-user-config`, `--ignore-rules`를 사용한다. 새 실행이며 resume/fork를 사용하지 않는다. 필요한 옵션이 없는 CLI는 실패한다. 사용자 설정·플러그인·MCP·훅·메모리·셸·컴퓨터/브라우저 도구 경로를 상속하지 않도록 기능을 끈다. 도구 실행 이벤트가 나타나면 중단한다.

개인 인증은 승인된 로컬 Codex auth 파일의 비공개 임시 복사본으로 사용하고 종료 후 제거한다. 인증 값은 로그·응답·Git에 넣지 않는다. 프로젝트와 별개인 임시 작업 폴더를 사용한다. macOS에서는 CLI 네이티브 파일 도구까지 포함하도록 외부 `sandbox-exec`로 임시 폴더 외 쓰기를 제한한다. Gatekeeper나 XProtect를 끄는 처리가 아니다. 실제 프로젝트의 편집 권한을 제공하지 않는다.

JSONL의 terminal turn과 종료 코드, 최종 JSON 아티팩트를 검사한다. 출력 아티팩트는 24KB, stdout+stderr 스트림은 1MiB, 시간은 기본 최대 120초다. 취소 시 자신이 만든 프로세스 그룹을 종료한다. 별도 deadline guardian이 Observer 강제 종료 후에도 실행 잠금과 제한 시간을 유지한다. 중단된 예약은 다음 실행에서 interrupted로 남고 자동 재실행하지 않는다. guardian/프로세스 종료는 실제 합성 자식 프로세스 테스트로 확인했다.

### macOS가 오래된 CLI를 차단한 사건

처음 PATH의 npm `0.106.0` 실행 파일이 없었고, 같은 옛 버전을 별도 개발 경로에서 설치해 확인하려던 중 사용자가 macOS의 악성코드 분류·휴지통 이동을 알렸다. 해당 경로의 사용을 중단했다. 차단된 파일을 복구하거나 quarantine 삭제, 재서명, 보안 설정 우회를 하지 않았다.

[OpenAI 공식 공지](https://openai.com/index/axios-developer-tool-compromise/)는 폐기된 이전 인증서 대신 새 인증서가 적용된 버전으로 업데이트하도록 안내하며 Codex CLI의 해당 최초 버전을 0.119.0으로 명시한다. 이번 Mac 알림의 원인이 정확히 인증서 폐기였다고 단정하지 않는다. 실제 사용은 이미 설치된 정상 실행·서명 검증된 최신 CLI로 전환했다. [공식 CLI 안내](https://learn.chatgpt.com/docs/cli), [비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode), [Apple 보안 안내](https://support.apple.com/en-us/102445)를 참고했다.

## DevinAcpAdapter — 실제와 Mock의 경계

설치된 Devin `3000.10.67 (0b186d6e)`의 `devin acp --help`를 확인했다. ACP v1 stdio JSON-RPC initialize → session/new → session/prompt → session/update 텍스트 청크 → end_turn을 구현했다. load/resume/기존 세션 ID를 입력받는 API가 없다. 실행마다 새 임시 작업 공간과 독립 분석 세션만 만든다. 클라이언트 파일·터미널 기능을 false로 광고하고 MCP 서버 목록은 비운다. 자식 프로세스의 DEVIN_PERMISSION_MODE는 auto로 고정해 상위 환경의 dangerous 모드를 상속하지 않는다. 권한 요청은 취소로 응답하고 도구 사용/클라이언트 도구 요청이 나오면 분석을 실패시킨다. 대상 환경 검증·승인 설정 없이는 활성화하지 않는다.

**최초 실제 확인:** initialize 응답의 protocolVersion=1, 기능 목록, session/new 성공. Devin이 new 응답 전에 초기 session/update를 보내는 동작을 관측해 반환된 새 session ID와 대조하는 처리를 추가했다. session/prompt는 `Please log in to use Devin. Use /login to authenticate again.` 오류로 끝났다. 해당 분석 세션에만 cancel을 보내고 연결을 닫았다. 기존 작업 세션은 로드하거나 제어하지 않았다.

**인증 후 실제 확인:** 설치된 `devin auth status/login --help`로 공식 로그인 경로를 확인했다. 일반 브라우저 로그인 선택 후 기존 개인 브라우저 인증으로 비대화형 사용자 개입 없이 완료됐다. 계정은 개인 Free/Enterprise=no임을 확인했다. 인증 파일이나 값은 제품 로그나 Git에 기록하지 않았다. 이후 새 독립 분석 세션에서 실제 청크를 수신해 빈 패치 smoke test가 성공했다. 추가 opt-in 통합 테스트는 두 합성 세션의 구현·실패·블로커·다음 행동을 실제 Devin ACP로 분석해 6개 항목을 적용했고, 인간 메모 보존과 무변경 0호출도 통과했다. 기존 작업 세션을 로드하지 않았다.

**Mock/합성 프로세스 검증:** 청크 조립, 신규 세션만 사용, JSON 검사, 버전 불일치, 권한/파일 요청 거부, 도구 사용 중단, 잘못된 세션 ID, 인증 오류, 단절, 타임아웃, 취소, 출력 초과, 독립 동시 실행. 초기 ACP 실행은 집계 필드 파서가 없어 null/unknown으로 기록했다. 후속 실제 응답에서 usage.inputTokens/outputTokens/totalTokens/cachedReadTokens를 확인해 해당 관측 형식의 파서를 구현했다. 정수·범위·총합을 검사하며 이 형식이 없거나 불일치하면 여전히 null/unknown이다. cachedReadTokens를 입력에 다시 더하지 않는다. 이는 모든 ACP 구현이 같은 집계를 보장한다는 뜻은 아니다.

**미검증:** 사내 SSO/조직 정책, 실제 위험 도구 호출에 대한 차단, 다른 ACP 구현/사내 모델의 사용량 형식, 사내 환경 동시 실행. 형식 보정은 잘못된 해석 자체의 정확성을 보장하지 않는다. 실제 성공 사례는 도구 사용 없이 JSON만 반환한 경우다. 로컬 프로젝트 deny 설정은 보조 수단이며 native 에이전트 전체의 도구 격리를 입증하지 않는다. Devin 자체의 계정/진단 정책은 Observer 수집기의 무텔레메트리 보장과 구분한다. 이 어댑터를 사내 운영 준비 완료로 보고하지 않는다. [ACP v1 공식 문서](https://agentclientprotocol.com/protocol/v1/initialization)와 설치된 Devin의 권한 문서를 기준으로 구현했다.

## 실행 정책과 예산

설정의 semantic.enabled가 기본 비활성이다. 개인은 codex_exec, 사내는 devin_acp를 명시한다. internal + codex_exec 조합은 거부한다. ACP는 추가 acp_approved 설정을 요구한다. 이는 운영자가 대상 환경을 확인했다는 설정이며 인증이나 조직 승인을 대신하지 않는다. 어댑터 실패 시 다른 제공자로 폴백하지 않는다. 회사 데이터인지 자동 판별해 주는 기능은 없으므로 작업 공간·저장소·환경의 분리는 운영자가 유지해야 한다.

기본 한도는 저장소별 UTC 하루 최대 8회, 태스크별 4회, 일일 예약 640,000토큰, 태스크별 예약 320,768토큰이다. 보통 1회 예약은 80,192토큰이며 복수 한도 중 먼저 소진되는 것이 적용된다. 실패/중단도 예약을 유지한다. 실제 사용량이 더 크면 이후 예산 계산에 큰 쪽을 사용한다. 동일 저장소의 실행 잠금으로 중복 호출과 동시 예약을 막는다. 개별 저장소 간 예산은 공유하지 않는다.

**예약은 제공자의 과금 토큰 상한 보장이 아니다.** 확인한 Codex exec/Devin ACP 경로에는 동일하게 강제할 수 있는 per-run token ceiling이 없다. 사전 예약·호출 수·시간·입출력 크기를 제한하고 가능한 실제 사용량을 기록한다. 알 수 없는 사용량을 0으로 기록하지 않는다. 기존 P4 Ollama 실험의 별도 예산과 합산되는 공통 과금 시스템은 아니다.

## 실제 수직 슬라이스의 증거

격리된 기존 개인 합성 작업 공간에서 새 M2 A·B 세션을 GUI로 만들었다. 도구·파일·명령·외부 리소스를 사용하지 않고 지정된 합성 자연어 상태 보고만 응답하도록 했다. 이는 테스트 재현을 위한 입력이며 실사용에 별도 보고 형식이나 agent-side 등록을 요구하지 않는다.

1. A는 구현 완료 보고, 테스트 진행, 호환성 유지 결정과 v2 지원 질문을 보고했다. B는 v2 인터페이스 때문에 테스트 실패, 호환성 블로커, 구현 수정 후 재실행, 아직 미결정인 v2 지원을 보고했다.
2. 브라우저에서 태스크를 만들고 A·B를 연결했다. 인간 결정을 메모로 저장하고 고정한 뒤 미저장 초안을 작성했다.
3. Semantic Refresh 한 번으로 6개 연산이 자동 적용됐다. 구현 완료 보고/테스트 진행/테스트 실패/블로커/질문/다음 행동이 세션별 근거와 함께 표시됐다. 기존 인간 결정은 유지됐다. 첫 실행: **입력 12,889, 출력 653토큰**.
4. 원본 보기로 실제 A의 hash-checked 응답을 열었다. 서비스 재시작 후 저장 상태와 고정 메모가 복원됐고 열린 페이지의 초안도 유지됐다. 같은 증분의 Semantic Refresh는 **모델 호출 0회**, 실행 원장 추가 0건이었다.
5. B에 후속 합성 보고를 추가했다: 호환성 수정 완료 보고, 블로커 해소 판단, 재실행은 아직 대기, v2 지원과 기존 호환성 유지 결정. 새 증분만 분석해 6개 연산을 적용했다. 블로커/질문은 reported resolved, 이전 다음 행동은 superseded, 새 다음 행동은 테스트 재실행으로 저장됐다. 승인 요청은 0건이었다. 두 편집 초안은 그대로 남았다. 두 번째 실행: **입력 12,948, 출력 649토큰**.
6. 후속 분석 직후 실제 합성 저장소에는 2개 applied 실행, 9개 지속 항목, 12개 항목 이력, 승인 대기 0건이 있었고 SQLite integrity_check=ok였다. 인간 메모/핀과 두 태스크–세션 연결을 유지했다.
7. 이후 브라우저에서 기계 항목 하나를 직접 교정·고정해 인간 소유 전환을 확인했다. 다시 Semantic Refresh를 눌러도 모델 0호출이고 교정/핀은 유지됐다. 해결·대체된 항목은 접을 수 있는 이전 기록으로 구분했다. 페이지 전체 재로드 때의 미저장 초안 보존은 약속하지 않으며, 서비스 재시작·분석 중 초안 보존과 구분해 검증했다.

이 두 실행에서 CLI가 보고한 합계는 **27,139토큰**이다. 전체 개발 과정의 총 토큰이나 과금액을 뜻하지 않는다. 별도의 실제 CLI 통합 테스트는 임시 합성 SQLite 두 세션을 사용하며 결과와 usage를 확인한다. 모델 출력의 항목 수와 표현은 실행마다 달라질 수 있다.

실제 모델 반복 검증에서는 invalid_patch_target 거부가 발생했다. ACP가 인간 항목 ID를 flag_conflict 대상으로 반환한 사례도 확인했다. 상태/커서는 보존됐다. 패치 내부의 새 key 참조 처리와 지침을 보완하고 회귀 테스트를 추가했다. 잘못된 참조를 자동으로 정답으로 간주하거나 테스트를 무시하지 않았다. 실행별 허용 대상 스키마와 최대 1회 예산 내 형식 보정을 추가한 뒤 실제 두 어댑터를 재검증했다. 또 합성 peer 템플릿의 MODE 치환이 환경 변수명까지 바꾸던 테스트 코드 결함을 고쳐 모든 프로토콜 오류 테스트를 다시 실행했다. 실패 후 명시적 재시도와 원장 유지 경로도 별도로 시험한다.

## 남은 제약과 다음 작업

- 수동 Semantic Refresh 이후의 자동 상태 반영까지다. 자동 의미 분석 스케줄은 아직 없다. 기본 모델 off 상태에서도 수집·계획·리소스·인간 View는 계속 작동한다.
- JSON/근거/소유권 검증은 해석의 진실성을 증명하지 않는다. 예시, 인용, 농담, 주입된 지시를 모델이 오해할 수 있다. 표본의 정상 결과를 전체 품질 보장으로 확대하지 않는다.
- 출처 본문은 보관하지 않는다. 해석 전에 사라지거나 바뀐 과거 본문은 복구할 수 없고 semantic_source_gap으로 해당 배치를 중단한다. 이미 저장한 항목의 근거 변경도 명시적으로 표시한다. 이 버전에는 불완전한 과거 의미 증분을 자동 폐기하는 복구가 없다.
- 선택되는 과거 문맥은 제한된 관련 항목이다. 임의의 오래된 원문을 자동 탐색하거나 모든 업무 유형을 이해하는 엔진은 없다. 단일 큰 이벤트/새 블록 형식은 안전하게 실패한다.
- 관측된 Desktop Local schema 17만 지원한다. 세션 간 전체 시간 순서, 실제 테스트 완료와 외부 PR/티켓 상태를 확정하지 않는다. 동일 텍스트의 모든 원본 복제본을 의미 항목에 자동 부착하는 기능은 없다.
- 상태의 실제 신선도와 해석의 정확성은 별개다. `current`는 현재 처리 가능한 관측까지 반영했다는 뜻이며 업무 완료·완전한 트랜스크립트 해석을 뜻하지 않는다.
- 다음 작업은 사내 승인 환경에서 ACP SSO·조직 정책·도구 격리·사용량 검증, 라벨된 의미 품질 평가 확대, 개인 프로젝트 dogfood다. 오류/누락률과 비용을 측정한 뒤에만 자동 트리거를 검토한다.


## 재현 가능한 실행과 현재 로컬 상태

개발 검증 명령은 `python3 -m unittest discover -s tests -q`다. 실제 모델 테스트를 포함하려면 승인된 개인 CLI 경로를 `OBSERVER_LIVE_CODEX`, 개인 ACP 경로를 `OBSERVER_LIVE_DEVIN_ACP`로 명시한다. Git 픽스처 테스트는 유효한 Git 경로를 `DEVIN_OBSERVER_GIT`로 지정할 수 있다. 테스트나 앱이 Codex를 설치하지 않는다.

M2 검증 인스턴스는 `http://127.0.0.1:8771/`에서 별도의 개인 합성 설정/저장소로 실행했다. 기존 M1 설정과 저장소를 교체하지 않았다. 실행 중인 프로세스는 로그인 자동 실행 등록을 뜻하지 않는다. 원본 DB, 인증 파일, 원본 본문, 실행 중 생성된 합성 저장소와 스크린샷은 Git에 포함하지 않는다. 사내 실제 사용 전 필요한 개입은 승인된 환경의 Devin 인증 및 운영 정책 확인이며, 개인 Codex/Devin ACP 경로 검증에는 추가 사용자 조작이 필요하지 않았다.

## 설계 대조 후속 점검

[전체 설계·증분 설계·구현 갭 점검](DESIGN_GAP_AUDIT.md)은 기준 코드 `f20696d`를 대조하고 5개 합성 경계 사례를 추가로 실행한 결과다. 미처리 원본 재작성 후 재개 부재, 혼합 세션 근거의 상태 변경 조건, 연결 scope 변경 뒤 신선도 무효화 부재, 보류 상태 변경의 UI 처리 누락과 재서술 중복 한계를 확인했다. 이는 수정 완료 기록이 아니다. 이번 재실행은 158개 중 156개 통과·실제 모델 2개 skip이며, 앞서 기록한 실제 CLI 통합 실행을 다시 수행한 것은 아니다. 정상 수직 슬라이스의 통과와 지속 추적 제품의 완성을 구분한다.
