# M3 — Cooperative Task Tracking

2026-10-30. `p0/desktop-probe`와 기존 [Draft PR #1](https://github.com/neocjmix/devin-task-observer/pull/1)을 이어서 작업했다.
M3-S02/S03의 시작 기준선은 M3-S01 커밋 `65420919b11b75acc2f8eae630b7ee0ddb02a3ba`다.

**파일 상태·협조형 CLI·스킬/훅·메뉴 막대·독립 수집·보존 이관 경로를 구현했다.** 실제 개인 합성
Devin 세션 A의 구현 보고와 세션 B의 실패·블로커·다음 행동 보고가 같은 태스크에 보존됐다.
A는 후속 작업에서 추가 보고 지시 없이 B의 상태를 읽고 새 보고를 커밋했다. 이 과정의
충돌·고정값 보호는 검증됐지만, A가 보고한 완료 내용에는 독립 검사에서 발견한 오류가 남았다.
접근성 승인 후 실제 메뉴 드롭다운·상세·보고 OFF 표시와 수동 수집 클릭도 확인했다.
개인 기존 DB의 실제 이관과 장기 사용은 완료로 보고하지 않는다.
기능별 증거와 최종 상태는 [슬라이스 목록](SLICES.md)을 따른다.

사용자는 `998978a`를 개인 실사용 기준선으로 확정하고, 이후 실제 사용 중 상태 업데이트를
직접 테스트하기로 했다. 당시 추가 구현을 멈추고, [기준선 기록](SLICES.md#개인-실사용-기준선-확정--2026-10-30)에
고정 커밋·검증 범위·미검증 항목과 후속 작업 기준을 남겼다.
이후 사용자 요청으로 메뉴 깊이·문구·작은 그래픽 요소만 [M3-S04](slices/M3-S04.md)에서 정리했다.
아래 S01~S03 실행 결과는 당시 기록이며, 현재 UI 변경 검증은 S04를 따른다.

## 적용한 설계

[최신 설계 변경안](DESIGN_CHANGE_PROPOSAL_2026-10-30_KO.md)과
[상태 트랜잭션 계약](STATE_TRANSACTION_CONTRACT_2026-10-30_KO.md)이 M3의 기준이다.
기본 관측은 기존 결정론적 수집기가 담당하고, 의미 판단은 작업 중인 세션이 자신의 문맥에서
수행한다. 세션은 설치된 스킬로 CLI를 사용하며 추적 항목을 직접 정의·갱신·보관한다.
Observer가 전체 대화록을 별도 모델에 전달하거나 기존 작업 세션을 깨워 질문하지 않는다.

새 태스크의 원본은 JSON 상태·이력·처리 기록이다. 읽기 후 판단하는 동안 락을 잡지 않고,
커밋 때 revision과 보호 규칙을 검사한다. 충돌하면 최신 값과 작성자를 돌려주고 세션이 다시
판단한다. 같은 항목의 최신 유효 커밋을 현재 값으로 사용한다. 명시적으로 고정한 값,
인간 메모와 이력은 보고가 덮어쓰지 못한다. 사람의 비고정 추적값은 후속 보고로 갱신할 수 있다.

기존 SQLite는 수집 체크포인트·관측과 이관 전 태스크 영역에서 계속 사용한다. 모든 영속
상태를 파일로 바꿨다고 설명하지 않는다. M2의 별도 모델 분석은 유지하지만 기본 비활성화이며
M3의 메뉴 조회·수집·CLI는 모델을 호출하지 않는다. 세션 자체의 판단·보고에는 모델 토큰이 든다.

보고 시각과 항목의 작성 세션을 별도로 표시한다. 등록한 ID는 인증된 신원이라는 뜻이 아니다.

## 실제 Devin 수용 실험

설치된 Devin Local/CLI `3000.10.67`을 사용했다. 새 개인 합성 workspace와 새 세션만 만들었고
기존 사용자 작업 세션을 재개·점유하지 않았다. A와 B는 같은 파일 태스크 `m3-live`에 기여했다.
B는 A의 초기 `tiny_parser.py`를 별도 workspace로 복사한 뒤 검증했으므로 A의 이후 수정과
B의 복사본 결과는 서로 다른 근거다.

### A: Desktop 구현 보고와 충돌 복구

- 새 Desktop 세션 `colorful-zinc`에서 SessionStart context 전달, 스킬 호출, `whoami`,
  태스크 연결·보고 ON을 확인했다.
- 실제 `parse_count` 구현과 unittest 2개를 작성·실행해 통과했다. 구현·테스트 작성·실행
  결과의 추적 항목 3개를 세션이 직접 보고했다.
- 중간에 인간 메모를 추가하여 오래된 revision의 보고를 거절시켰다. 세션은 다시 읽고
  후속 제출을 성공시켰으며 인간 메모는 보존됐다. 이후 테스트 작성 항목을 인간이 고정했다.
- 초기 스킬에서 연결 순서·필수 expected revision 안내가 부족한 점을 발견하여
  `whoami → 읽기 → 필요 시 연결 → 재조회 → ON → 재조회 → 보고` 순서로 구체화했다.
- Desktop의 명령 승인 요청은 합성 작업에 필요한 개별 명령만 승인했다. 스킬 설치만으로
  호스트 권한을 자동 취득하거나 모든 도구를 무인 실행한 결과는 아니다.
- **후속 보고 성공:** 추가 보고 요청 없이 변경된 작업을 수행한 뒤 스스로 기존 상태를 읽고
  보고했다. expected revision 10과 실제 12의 충돌로 거절된 뒤 B의 최신 값을 다시 읽었다.
  이후 고정 항목 변경도 `pinned_item`으로 거절됐다. 고정 항목을 제외하고 새 보고 ID로
  제출하여 revision 13에 커밋했다. 인간 메모 1개와 고정 항목의 commit sequence 6은 보존됐다.
- A는 자신의 구현·테스트 값과 B가 정의한 블로커·다음 행동을 갱신했다. 두 항목의 현재
  작성자는 A이고 상태는 `completed`다. B의 최초 실패 관측 항목은 B의 출처로 남고 이전 값은
  이력에 보존됐다. 이는 최신 유효 커밋을 신뢰하고 최종 의미 조정을 세션에 맡긴 설계의 결과다.
- **내용 정확성 한계:** A는 `isdigit()` 검사로 비ASCII 입력도 거절한다고 보고했지만 독립 실행에서
  `'１２'`는 여전히 12가 됐다. `'1_000'`과 `'+12'`는 ValueError로 거절됐다. 따라서 합성 작업의
  ASCII 전용 요구 자체는 완성되지 않았다. 상태의 `reported` 표시는 유지하며, 보고 수용 성공을
  구현 정확성의 보증으로 승격하거나 별도 의미 판정기를 추가하지 않았다.
- **실제 보고 중단:** A에 중단을 요청하자 스킬 경로에서 현재 상태를 읽고 A의 기여만 OFF로
  변경했다. revision 14에서 A OFF·B2 OFF·B3 ON을 확인했다. 항목 6개·인간 메모 1개·고정 항목의
  commit sequence 6·이력 파일 14개는 유지됐다. 다른 세션의 보고 설정을 함께 끄지 않았다.

### B: 실패한 두 시도와 성공한 세 번째 시도

| 실행 | 실제 결과 | 판정 |
|---|---|---|
| B1 `voltaic-pick`, 비대화형 `-p` | 스킬·hook ID는 전달됨. sandbox에서 state commit lock 접근 실패, 테스트 파일 쓰기는 승인 필요. 28.52초, exit 0 | 수용 실패: 테스트·보고 없음. 태스크 미연결 |
| B2 `mica-pentagon`, 전용 `--config` | 정확한 state root/lock 쓰기 범위를 추가해 읽기·연결·ON 성공. 직접 파일 쓰기는 비대화형 승인 단계에서 중단. 39.067초, exit 0 | 수용 실패: 테스트·보고 없음. 이후 관리 명령으로 이 기여만 OFF, 이력 보존 |
| B3 `shared-currant`, 대화형 PTY | sandbox 유지. 합성 테스트·보고 파일 두 개를 정상 일회 승인. 테스트 실패를 실행하고 세 항목을 직접 보고·재조회. `/exit` 정상 종료 | 수용 성공: 실제 실패와 보고 커밋 확인 |

설치된 CLI 도움말·권한 문서를 확인하고 실행했다. B1/B2의 exit 0을 제품 수용 성공으로
계산하지 않았다. `dangerous` 모드나 전역 blanket 허용으로 우회하지 않았으며 도구가 요구한
일회 승인으로 B3를 진행했다. B2의 불완전한 ON 상태는 revision 12에서 OFF로 정리했다.
B1/B2 세션이나 기록을 삭제하지 않았다.

B3는 ASCII 숫자만 허용한다는 요구에 따라 `parse_count('1_000')`가 ValueError를 내야 한다는
테스트를 작성했다. `python3 -m unittest test_b_validation -v`는 실제로 **1개 실패,
exit 1, `ValueError not raised`**였다. 이는 의도적으로 발견한 합성 구현의 결함이며 Observer
회귀 테스트 실패가 아니다. 세션은 구현을 수정하지 않고 다음을 스스로 정의해 revision 11에 커밋했다.

| 보고 항목 | 세션이 선택한 상태 | 내용 |
|---|---|---|
| `validation-failure-underscore-syntax` | completed | 검증 수행 완료, 실제 테스트는 실패했다는 값·제목 |
| `clarified-interface-blocker` | blocked | Python `int()`가 밑줄을 허용하여 명시된 인터페이스와 불일치 |
| `implementation-correction-revalidation` | pending | 구현 수정 후 재검증 필요 |

각 항목에 작성 세션과 파일 근거가 있으며 A의 항목·인간 메모·고정값이 유지됐다.
`completed`가 테스트 성공을 뜻하지 않는 이 사례는 status의 의미를 세션이 정의한다는 실제
한계다. Core는 내용의 의미나 파일 존재를 독립 검증하지 않는다. 항목을 `reported`로 저장하며
제목·값·근거를 함께 봐야 한다. 다른 workspace의 결과를 전역 최신 정답으로 자동 합치지 않는다.

| 실제 화면 클릭 | 최초 CUA의 창 없는 앱 연결 시도는 실패. 후속 사용자 접근성 승인 뒤 실제 상태 아이콘·태스크 하위 메뉴·항목 상세·세션 OFF·수동 수집 클릭과 화면 캡처 확인 |

### 후속 실제 메뉴 UI 검증

최초에는 CUA가 창 없는 accessory 앱에 연결하지 못해 Cocoa 객체까지만 확인했다. 이후
사용자가 직접 접근성 권한을 승인·인증했고, System Events의 UI 접근이 활성화된 뒤 실제
상태 막대의 `◉` 아이콘을 클릭했다. 이 후속 결과는 이전 미검증 상태를 해소하며, 권한이
자동으로 부여됐거나 최초 CUA 시도가 성공했다는 의미는 아니다.

- 태스크 하위 메뉴에서 revision 14, 추적 항목 6개, 인간 고정값과 메모를 확인했다.
- `test-execution` 상세에서 마지막 작성 세션 `colorful-zinc`와 독립 검증 사실이 아닌
  세션 보고라는 표시를 확인했다.
- A 기여에서 보고 OFF와 마지막 Stop 활동이 표시됐다.
- 실제 수동 수집 메뉴를 클릭했다. 증거 파일은 클릭 처리 0.776초·관측된 수집 간격
  0.819초, `last_error: null`, 상태 파일 해시 불변을 기록한다. 이는 한 번의 로컬 실행
  관측이며 지속 성능의 보장은 아니다.

증거는 실험실의 `native-menu-ui-acceptance.json`과 `screenshots/` 아래의
`observer-menu-open.png`, `observer-task-menu.png`, `observer-menu-detail.png`,
`observer-session-off-full.png`다.
원본 스크린샷에는 다른 데스크톱 내용이 포함될 수 있어 로컬에만 보관하며 Git에 넣지 않는다.
이 후속 검증에는 제품 코드 변경·모델 호출·회귀 테스트 재실행이 없었다.
위 테스트 결과와 토큰 사용량은 기존 실행의 수치를 그대로 유지한다.

원본 대화록·DB·개인 설정·앱·진단 산출물은 Git에 넣지 않는다. 최소 로컬 증거는

## 로컬 사용 경계와 남은 제약

- Python Core/CLI에 선택적 `rumps 0.4.0`·PyObjC Cocoa bridge를 더했다. Swift·Electron은 없다.
  현재 Mac의 로컬 alias 앱 실행기는 checkout·venv·설정 경로를 참조한다. 독립 배포·공증 앱이
  아니며 Python이나 Codex/Devin CLI를 앱에 복사하지 않는다. 자세한 실행·한도는
  [메뉴 검증 기록](slices/M3-S02_MENU.md)을 따른다.
- 로그인 자동 실행은 별도 명시적 선택이다. 실제 logout/login, 장기 상주, 다른 macOS/Python
  조합은 미검증이다. 실행 중 설정 변경은 혼합 적용하지 않고 재시작 필요를 알린다.
- 실제 resume/compaction 이후 지속 보고와 반복 후속 턴의 보고 충실도는 이번 A/B 성공만으로
  증명되지 않는다. 훅/스킬은 최선의 자발적 보고를 돕고 매 턴 보고를 강제하지 않는다.
- 자유 상태값은 세션이 의미를 정한다. 사실 확인·충돌 의미 조정·근거 내용의 진실성을 Core가
  대신 결정하지 않는다. 인간 고정·출처·이력·조건부 커밋은 이 불확실성과 별개로 보호한다.
- 파일 손상과 규약 밖 편집은 원문·오류·마지막 정상 상태를 보존한다. 임의 외부 writer나
  하드웨어 전원 장애까지 완전한 원자성을 보장하지 않는다. 이력의 장기 증가·보관 정책은 남아 있다.
- 이관은 새 전용 root만 지원한다. 실제 사용자 DB 이관, 기존 파일 root 병합은 하지 않았다.
  legacy View·자원·확인 위치는 가져온 스냅샷이며 새 메뉴의 전체 편집·확인 workflow가 아니다.
  후속 파일 변경이 있으면 보수적 롤백을 거절한다. 구·신 DB를 양방향 갱신하거나 자동 전환하지 않는다.

장기 실행과 개인 데이터 전환은 별도 검증 범위로 유지한다. 테스트 수나 합성 보고 성공을
모든 실제 작업에서 수동 정리가 사라진다는 보장으로 해석하지 않는다.
