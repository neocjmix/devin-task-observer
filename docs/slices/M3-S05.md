## 구현 범위

```text
~/.devin-task-observer/
  config.json             # 명시적으로 선택한 작업 공간과 수집 설정
  observer.sqlite3        # 결정론적 관측·체크포인트
  state/
    tasks/                # 태스크 JSON, 메모·고정값, 변경 이력
    reports/              # 중복 보고 방지 영수증
    sessions/             # 훅에서 받은 세션 식별·활동 기록
    integrations/         # 설치한 훅·스킬의 소유권 기록
    ui/                   # 확인 위치를 저장한 경우 생성
    .transactions/        # 중단된 커밋 복구
    .lock
```

- CLI·수집기·양쪽 UI·설치 스크립트가 `observer/paths.py`의 기본값을 공유한다.
  명시적 경로는 우선하며, 일반 실행·configure가 기존 저장소를 추측해 병합하지 않는다.
- `menu-runtime`은 실행 의존성이므로 기존 Application Support에 유지한다.
  Python이나 모델 CLI를 앱에 복사하지 않는다.
- 관리형 앱 런처는 정확한 기존 config/root를 함께 지정해야 다른 경로로 재연결할 수 있다.
  수정된 런처는 거절하고 원본 백업·원자적 파일 교체·반복 실행 무변경을 유지한다.
  런처 전환 명령 자체는 데이터를 이관하지 않는다.
- 이전 파일 root는 원래 `.lock`을 유지하고 `.relocated.json`에 새 위치를 기록한다.
  락을 얻은 뒤 이를 검사하므로 이전에 생성된 Core 인스턴스와 대기 중인 writer도
  `relocated_store`로 중단된다. 자동 전달은 하지 않는다. 손상된 marker도 원문을 보존하며
  접근을 중단한다. 이전 root의 훅은 실패 시 `{}`/exit 0으로 원래 Devin 작업을 계속하게 한다.

## 이 Mac에서 실제 수행한 이전

활성 M3 앱만 정상 종료하고 수집 서비스·수집 DB·파일 상태의 기존 락을 확보했다.
원본 상태·DB·설정·워크스페이스 소유 파일·런처를 비공개 백업한 뒤 별도 임시 폴더에 복사했다.
미완료 트랜잭션이 없음을 확인했고 SQLite backup API의 스냅샷을 사용했다.

설치 두 곳의 기존 스킬 본문·훅·소유권 checksum을 검증하고 **이전 root 문자열만** 바꿨다.
무관한 훅과 도구 권한은 보존했다. 프로젝트 로컬 권한 설정도 같은 데이터의 새 위치만 가리키도록
치환했다. 복사된 활동 기록 8개의 `needs_context`를 켜 다음 정상 훅에서 새 경로를 안내하게 했다.
세션 ID·기존 활동 시각은 보존했다. 기존 실행 세션에 프롬프트를 보내지 않았다.

임시 폴더를 새 홈 경로로 게시하고 이전 root를 차단한 뒤 런처를 재연결했다.
이전 루트의 lock inode와 원본 파일은 보존했다. 작업 단계와 원본 바인딩은 로컬 복구 기록에 남겼다.
여러 워크스페이스·런처를 포함한 전체 유지보수 작업이 단일 원자적 트랜잭션이라는 보장은 하지 않는다.
이번 이전은 해당 설치를 검증해 수행한 유지보수이며 범용 자동 이관 기능을 추가한 것이 아니다.

## 남은 경계

- 기존 대화에 캐시된 도구 권한과 옛 경로가 새 정상 훅 이후 갱신되는 실제 후속 Devin 턴은
  미검증이다. 옛 root로 쓰면 안전하게 거절하며 스킬·새 경로 재조회가 필요하다.
- 이전 실험 디렉토리와 별도 M2 SQLite/프로세스는 보존했다. 활성 M3 저장소와 다른
  실험 결과를 자동 병합하거나 삭제하지 않았다. 새 로그인 자동 실행은 등록하지 않았다.
- 새 데이터 홈은 0700, 복사한 상태 파일은 0600이다. 같은 사용자 권한의 임의 직접 writer가
  marker와 락을 무시하는 경우까지 막는 보안 경계는 아니다.
