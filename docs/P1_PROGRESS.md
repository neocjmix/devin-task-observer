# P1: Local adapter and checkpoints (in progress)

Status: **not complete**. This is a narrow prototype for the observed Devin Local schema; it does not yet implement the full normalized event contract. The downstream prototype and its limitations are documented in [P2](P2_PROGRESS.md) and [P3](P3_PROGRESS.md).

## Implemented

- `observer.devin_local.read_sessions` opens the source SQLite database using `mode=ro` and `query_only`, in a short read transaction, with a bounded lock timeout. It reads only explicitly selected workspace paths and requires the observed schema migration version 17. It fails closed on an unrecognized schema, malformed JSON, missing message IDs or an invalid active chain. It reads node metadata and hashes JSON payloads without persisting message bodies.
- The local SQLite store records session metadata, node identities, hashes and immutable added/modified/missing/restored observations. Observation changes and checkpoints commit together. Missing nodes, identity changes, and conflicting duplicate message IDs mark a session stale; data and prior observations are retained. A missing session is marked stale. Structural staleness is deliberately sticky; an explicit recovery workflow remains to be designed. A transient source-read failure clears after a subsequent complete read if no structural anomaly exists.
- For observed node shapes, the store records conservative `user`, `assistant`, `tool_call`, `tool_result`, `plan`, or `unknown` labels per node hash. `plan` is limited to the observed `todo_write` call. A preliminary event index groups evidence by session, message ID, type and tool-call ID; it keeps all contributing node references and hashes. Unrecognized shapes remain `unknown`. The index is not yet a verified complete ordered timeline or transcript.
- Evidence can be read on demand from the source only when workspace, session, node and content hash match. A changed or missing source returns an error instead of silently returning a different version. Raw source JSON is returned in memory to the caller; it may contain injected context or sensitive data and is not stored in the observer DB. Old content cannot be recovered if Devin removes it from the source.
- A manual refresh and optional polling CLI use an explicit workspace allowlist. A local file lock serializes CLI refreshes; an unavailable source leaves checkpoints unchanged and marks known sessions stale. No hooks, network requests, model calls or Devin session control are involved. SQLite WAL readers may use shared-memory coordination and briefly hold read locks.
- The CLI checks the source file's device and inode before and after reading, and marks existing history stale when a later successful refresh sees a replacement. This detects tested replacements, but is not a proof against all filesystem races or in-place rewrites.
- The observer store is rejected if it is the source database or located in its directory. New store and lock files are created with restrictive permissions. Files contain personal session metadata and hashes; keep them local and out of Git.

## Actual validation

- A live run against **three newly created synthetic Desktop sessions** stored 201 node observations; immediate replay stored zero more. During a subsequent synthetic session update, a refresh recorded three new transitions and its immediate replay recorded zero; the Desktop session then completed its response. This is a limited sample, not proof of lossless collection across all timing scenarios.
- In a separate Desktop test the agent read only the synthetic `README.txt` and returned its first word. The Local store contained an assistant node with a `tool_calls` list and a `role: tool` result node with `tool_call_id`. A live refresh labeled two duplicated call nodes and one result node. After the subsequent plan test, the preliminary event index identified two distinct tool calls and found matching result IDs for both; contributing nodes were retained.
- A separate synthetic `todo_write` request displayed two tasks in Desktop. Its assistant node carried a tool call named `todo_write` with object arguments. The observer recorded six changes and two plan-labeled nodes (duplicates retained), then zero changes on immediate replay. This is a single plan shape, not evidence for all planning formats.
- An on-demand evidence lookup found the known synthetic user input in the live Local source after checking its stored hash. Tests reject a different workspace and a changed source node. This confirms retrieval of that sample, not complete prompt extraction.
- The P1 collector was run before and after a second normal Desktop restart: both runs found three synthetic sessions, with zero new transitions and zero stale sessions after restart.
- After that tool-call test, a fresh CLI run observed 210 nodes in three sessions, and an immediate replay recorded zero transitions. An initial implementation marked one session stale because the same assistant message ID had differing JSON. In this sample the only difference was an added `metadata.extensions.chisel/tool_call_content`. The adapter now recognizes this exact additive variant while retaining both nodes and their distinct hashes; all other differing payloads remain ambiguous. A fresh live run recorded 210 transitions, then zero on replay, with zero stale sessions. This does not establish general tool-revision semantics.
- The P0/P1 synthetic tests cover append, same-length edit, replay, missing/restored nodes, reorder, a compaction-like head change retaining old evidence, disappearing sessions, duplicate identifiers and row-ID rewrite, conservative event labels, hash-checked evidence lookup, the observed additive tool metadata variant, malformed input, locked or missing source and recovery, source identity changes, concurrent CLI refresh exclusion, unknown source version, preventing writes to the source directory, failed checkpoint updates, and a process killed during a checkpoint transaction followed by replay. Probe tests cover snapshots, symlinks, missing sources and malformed chains. Tests do not use actual personal transcripts; the full suite count is reported in [P3 progress](P3_PROGRESS.md).

## Remaining before P1 acceptance

- Implement and validate normalized user/assistant/tool/plan events with sufficient evidence to reconstruct intended user input without confusing injected project context, internal user-role nodes, duplicate nodes, or compaction summaries. The current observations are **node-level metadata only**, not a usable transcript.
- Test changing and locked source databases during collection, source replacement/rewrite, concurrent refreshes, missing source recovery, and repeated compaction against both fixtures and live controlled sessions. Surface and resolve stale states; verify all atomicity and replay guarantees.
- Investigate WAL shared-memory effects and checkpoint delays under sustained load and observer crash. The current short live tests do not establish zero interference.
- Add version and source identity handling beyond this one observed migration. Other Desktop agent types and versions remain unverified. Do not infer universal support.
- Task views and a dashboard have been prototyped while P1 acceptance remains open; see [P2 progress](P2_PROGRESS.md) and [P3 progress](P3_PROGRESS.md). Optional semantic reconciliation remains unimplemented.
