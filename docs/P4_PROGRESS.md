# P4: Optional local semantic suggestions (experimental)

Status: **partial experiment, not full semantic reconciliation**. The normal dashboard starts with analysis disabled. An explicit server flag enables a manual action; collection, polling and ordinary dashboard views never invoke a model. No network endpoint or model can be supplied by a client. The experimental implementation connects only to `127.0.0.1:11434` and requests the fixed `llama3.2:latest` model after checking local GGUF metadata. Its operation assumes the local Ollama service honestly serves its reported local model; it is not a network security audit of that separate service.

## Behavior and safeguards

- A human selects one present, classified user/assistant node from a linked session. The source workspace, session, node and stored hash are checked; no entire transcript or full history is passed. The text can still contain automatically injected context. Text longer than 600 UTF-8 bytes is rejected rather than truncated. Only the source content string is sent, not the JSON metadata. Results may be inaccurate or follow misleading source instructions; they are untrusted suggestions, not verified facts.
- Each unique task/session/message ID/hash/model/prompt-version is analyzed at most once, including duplicate nodes with identical message IDs and hashes; a repeat returns its existing outcome without a model call. This single-node cache intentionally does not incorporate a view revision: current view contents are not passed to this experiment. It does not provide multi-event reconciliation, conflict detection, or automatic task updates.
- Local requests specify 2,048 context tokens and at most 256 output tokens. Before a call, 2,304 tokens are reserved in a transactional UTC-day ledger with a fixed daily cap of 4,608 reserved tokens per observer database; failed, interrupted, or pending runs retain the reservation. Separate observer databases have separate budgets. Actual prompt/output token counts are recorded only when returned and validated. The cap assumes the local model server respects its requested limits. The ledger is local; no paid cloud API is involved. An interrupted pending run has no automatic retry or recovery workflow.
- The model may propose one new note, or an empty result. Output shape, size, source identity and budget are checked. A person must separately choose a section and explicitly accept the proposal; the insertion, evidence reference, item history, proposal status and view revision commit atomically. Existing notes and pins are not overwritten. A rejected proposal remains recorded; provenance stays visible on accepted notes. Generated text is stored in the private observer database and can repeat sensitive source content, even though raw transcript bodies are not stored.
- The fixed local model, small input limit and conservative two-reservation daily budget are deliberately narrow experimental constraints, not a general model configuration or production budget system.

## Observed test

On the personal Mac, the already-installed Ollama 0.15.2 and local `llama3.2:latest` were used with one **synthetic** Devin Desktop message. The browser requested a suggestion, received it without an automatic view change, and explicitly accepted it into the synthetic task. Its source reference and `local_model` origin remained visible after a server/browser reload. The model reported 79 prompt tokens and 21 output tokens; 2,304 tokens were conservatively reserved. Repeating the same request returned the cached outcome without consuming a second reservation. This single example demonstrates the plumbing, not the factual quality or safety of model interpretation.

The synthetic regression suite covers default-off behavior, no calls on cache hit, input and output validation, hard reservation exhaustion including concurrent requests, failure accounting, rejection, stale view revisions, retained human edits and pins, link scoping, and evidence-linked explicit acceptance. Tests with a simulated model do not prove real model behavior.

## Remaining

No automatic selection of relevant deltas, multi-event interpretation, affected-item context, non-destructive status proposals, conflicts, configurable reviewed models/budgets, robust retry/recovery, or model quality evaluation exists. The cache identifies the model by tag rather than content digest, so replacing the model behind that tag does not invalidate an existing result. P1's transcript and ordering limits still apply. Do not use this experiment to infer a verified task status.

Ollama's official [generate API](https://docs.ollama.com/api/generate) documents local generation and returned token counts; its [structured output documentation](https://docs.ollama.com/capabilities/structured-outputs) describes schema-formatted responses. Actual results are nevertheless validated locally and treated as untrusted.
