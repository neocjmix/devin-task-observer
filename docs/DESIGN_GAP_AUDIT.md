# 전체 설계·증분 설계·구현 갭 점검

2026-10-29. 점검 기준 코드는 `f20696de11cbbe833a84c80bb9ad25c286021104`다. README와 docs의 계획·설명·진행 기록을 코드에 대조했다. 이번 작업은 점검과 문서화이며 아래 결함의 수정은 포함하지 않는다.

현재 판정은 **읽기 전용 기반과 수동 의미 분석 수직 슬라이스는 구현됐지만, 지속적으로 믿고 읽을 수 있는 태스크 자동 추적 제품은 아직 완성되지 않았다**는 것이다. 임의의 완성률 퍼센트는 제시하지 않는다.

## 1. 전체 설계와 구현

| 합의한 설계 | 현재 구현 | 남은 갭과 성격 |
|---|---|---|
| 기존 Devin 작업 경로에 개입하지 않는 읽기 전용 Observer | Local SQLite 읽기, 별도 Observer DB, 작업 세션에 프롬프트를 보내지 않는 독립 분석 실행 | 방향 일치. WAL 잠금 영향·장시간 비간섭은 아직 충분히 검증하지 않음 |
| 태스크–세션 다대다 관계 | Contribution, 태스크별 리뷰 위치와 의미 커서 | 구현. 공유 세션의 내용별 태스크 소속은 scope를 모델에 전달하고 불확실성을 표시하는 방식이며, 의미적 오분류를 결정론적으로 증명/차단하지는 못함 |
| 한 번 연결한 뒤 현재 상태를 지속적으로 읽기 | 수집·리소스·계획은 자동 갱신. 자연어 상태는 수동 Semantic Refresh 뒤 자동 반영 | 제품 목표에는 갭. 단, M2 계약은 수동 실행부터 시작하도록 명시했으므로 자동 의미 분석 스케줄 부재 자체는 이번 단계의 위반이 아님 |
| 자유로운 태스크별 Persistent View | 인간 View의 자유 섹션·순서·메모·핀 보존. 기계 상태는 별도 영역 | 보호와 분리는 합의대로 구현. 자동 영역은 7개 고정 category이며 임의 섹션에 자동 항목을 배치하는 연결은 없음. propose_section 승인은 인간 View에 섹션만 생성함 |
| 진행·블로커·결정·질문·다음 행동의 안전한 유지 | 모델 JSON 패치, Core 검증, 이력, 인간 소유권 우선 | 정상 경로 구현. 혼합 출처 상태 변경, 범위 변경 무효화, 보류 변경 처리에 아래 재현된 갭이 있음 |
| 개인 Codex CLI / 사내 승인 Devin ACP | 외부 CLI 참조, 공통 SemanticModelAdapter, 독립 분석 세션 | 개인 실제 실행 기록 있음. 사내 SSO·조직 정책·위험 도구 격리의 실제 검증은 미완료 |
| 최소 설정과 계속 실행·복구 | observerctl, 설정, 재시작, 수집 backoff, 선택적 LaunchAgent | 프로세스 복구와 의미 증분 복구는 별개. 후자는 일부 원본 변경에서 막힘. 실제 로그인 주기·10+ 활성 세션 장시간 dogfood는 미검증 |
| 세션 재질문을 줄이는 제품 | 두 세션 합성 사례에서 상태와 근거 표시 | 재질문 감소율, 누락·과잉 주장률, 유용한 갱신당 비용을 측정한 제품 품질 평가가 없음 |

기준: [구현 계획](IMPLEMENTATION_PLAN.md), [데이터 계약](DATA_AND_RECONCILIATION.md), [제품 완료 기준](VALIDATION_AND_HANDOFF.md).

## 2. 증분 설계는 세 층을 구분해야 한다

| 층 | 실제 구현 | 판정 |
|---|---|---|
| 원본을 읽는 작업량 | 매 poll마다 선택된 세션 노드를 다시 읽고 JSON을 해석·해시 계산 | 원본 읽기 자체는 전체 재검사. 대규모 효율과 WAL 영향 검증이 남음 |
| 변경의 저장 | 노드 ID/해시 비교로 added/modified/missing/restored만 기록. 관측·체크포인트 함께 커밋 | 결정론적 증분 저장과 같은 스냅샷 재실행 중복 방지는 구현 |
| 의미 분석 입력 | 태스크–세션별 의미 커서 이후의 새 텍스트, 관련 기존 항목과 인간 문맥을 제한해서 전달 | 의미 입력은 증분. 전체 트랜스크립트 재요약은 하지 않음. 관련성 선택은 단어·세션·열린 상태 휴리스틱 |
| 오래된 문맥 조회 | 선택된 기존 항목과 그 근거 참조 사용 | 필요한 오래된 원문을 참조에 따라 추가 탐색하는 경로는 없음. 맥락 누락 가능 |
| 패치 적용과 커서 | revision/근거/권한 확인 후 항목·이력·처리 키·커서를 원자적으로 저장 | 정상 경로와 실패 보존 구현. JSON 형식 및 참조 유효성이 의미의 정확성을 보장하지는 않음 |
| 중복 방지 | 같은 메시지/텍스트 해시 재해석 방지, item key 또는 정규화된 동일 문장 비교 | 같은 증분 재실행은 0호출. 다른 증분의 같은 사실을 다르게 표현한 경우는 모델 key 선택에 의존 |
| 원본 변경·누락 | 이미 반영한 항목은 disputed_source 표시. 미처리 옛 해시가 없으면 배치 중단 | 안전하게 실패하지만 재개 정책이 없음. 한 세션의 옛 증거 때문에 태스크 전체 의미 분석이 막힐 수 있음 |
| 비용 | 조회·무변경 0호출, 크기·시간·호출·예약 한도 | 입력량이 작아도 검증 표본은 약 1.2만~1.5만 토큰/회. 80,192 예약은 실측 소비량이 아니며 과금 상한도 아님. 기본 전역 예약 한도로 보통 7회까지만 가능 |

코드: [원본 읽기](../observer/devin_local.py), [차분 저장](../observer/store.py), [의미 입력·적용](../observer/reconciliation.py).

## 3. 이번에 별도로 재현한 갭

`tests/test_reconciliation.py`의 임시 SQLite fixture와 FakeModel을 사용했다. 실제 Devin 원본을 바꾸지 않았고 실제 모델·네트워크 호출은 0회다. FakeModel에 의도적으로 잘못되거나 보수적으로 다뤄야 할 패치를 반환하게 해 Core의 경계를 확인했다. 따라서 이 결과는 **실제 모델이 이런 오판을 했다는 증거가 아니다**.

### G1. 미처리 원본 재작성 뒤 의미 분석 재개 경로 없음

관측된 assistant 노드를 첫 의미 분석 전에 수정하고 수집한 뒤 두 차례 재시도했다.

- 두 번 모두 `semantic_source_gap`.
- 모델 호출 0회, 의미 커서 0개, 대기 관측 4개 유지.
- 옛 본문이 보관되지 않아 같은 재시도만으로 해결되지 않는다. 수집기 구조 변경 확인은 의미 커서를 복구하지 않는다.
- 안전하게 중단하는 부분은 설계대로다. 공백을 명시적으로 기록하고 사용자가 동의한 새 기준에서 이어 가거나 독립적으로 처리 가능한 증거를 분리하는 복구 정책이 빠져 있다. 조용히 건너뛰는 수정은 허용되지 않는다.

근거: reconciliation.prepare의 과거 해시 일치 검사, `tests/test_reconciliation.py`의 source-gap 테스트.

### G2. 여러 세션 근거를 가진 항목의 자동 상태 변경 조건이 느슨함

A와 B 각각에 자기 인터페이스 불일치로 테스트가 차단됐다는 기록을 추가하고, 두 근거를 묶은 하나의 블로커를 만들었다. A에만 자기 문제를 고쳤다는 후속 보고를 추가하고 FakeModel이 전체 항목을 resolved로 바꾸는 패치를 반환하게 했다.

- 결과: `resolved`, 근거 세션 A/B, 승인 대기 0건.
- `_follows`는 옛 근거 중 하나와 새 근거 중 하나의 같은 세션 후속 관계만 증명해도 true다.
- `supersede`에는 기존 근거 세션 전체를 새 근거가 포함하는 검사도 있으나 `update_status`에는 없다.
- A가 자기 작업만 해결한 상황과 공유 블로커 전체를 해결한 상황을 Core가 구분하지 못한다. 모델이 충돌을 표시하지 않은 경우의 보수적 적용 조건과 회귀 검증이 필요하다.

근거: reconciliation._follows, _apply의 update_status/supersede 분기. 이는 혼합 출처의 오판 방어 갭이며 실제 모델 오류율을 측정한 결과는 아니다.

### G3. 태스크 연결 범위를 바꿔도 기존 의미 상태가 current

최초 분석 후 Contribution scope를 구현/테스트를 제외하는 문서 작업 범위로 바꿨다.

- 결과: 기존 항목 5개 유지, freshness `current`, Refresh는 `unchanged`, 모델 호출 0회.
- 실행 도중의 계약 변경은 revision/hash로 잡지만, 이미 완료된 분석 이후 범위 변경은 별도 무효화하지 않는다.
- 기존 항목을 지우면 안 된다. 대신 해석 기준이 변경됐음을 표시하고 재평가 범위·명시적 실행 정책을 정해야 한다. 조회 시 무조건 LLM을 호출하는 해결은 계약에 맞지 않는다.

근거: registry.update_contribution, reconciliation._rows/projection. 태스크 설명 등의 다른 계약 변경도 별도 검토 대상이며 이번 합성 재현은 scope 변경만 확인했다.

### G4. 보류된 상태 변경을 사용자가 처리하는 기능 경로 불완전

A의 블로커에 대해 후속 관계가 없는 B의 해결 보고를 받아 update_status가 승인 대기로 남는 정상적인 보수적 사례를 만들었다.

- API로 해당 제안을 승인하면 `explicit_item_correction_required`, 항목은 open으로 남음.
- UI는 이 제안에 거절만 제공하고 항목 수정으로 판단하라고 안내한다.
- 그러나 현재 의미 항목 수정 UI는 본문과 핀만 바꿀 수 있고 status 변경 컨트롤은 없다. status를 수정하는 백엔드 API는 있다.
- 이는 화면 꾸미기가 아니라 보류된 판단을 끝내는 기능 연결의 누락이다.

근거: reconciliation.resolve_pending/correct_item, web/live.js의 의미 항목 편집 및 제안 버튼.

### G5. 재서술된 같은 사실의 의미 중복 방지는 보장되지 않음

같은 세션 B의 첫 증분에서 “Tests fail because the interface changed.”, 다음 증분에서 “Interface mismatch is causing test failures.”를 서로 다른 key로 추가하게 했다.

- 결과: 두 항목 모두 저장됨.
- 동일 key/동일 정규화 문장/동일 증분에 대한 결정론적 중복 방지는 있다. 뜻이 같은 다른 문장까지 Core가 판별하는 것은 아니다.
- 모델에 안정적인 key 재사용을 지시하고 관련 항목을 제공하지만 그 품질은 평가되지 않았다. 장기 누적 중복률을 측정해야 한다. 이 문제만으로 범용 의미 중복 엔진을 새로 만드는 것은 과도하다.

근거: reconciliation._apply의 add 비교 조건 및 입력 관련성 선택.

## 4. 검증된 것과 아직 검증되지 않은 것

- 이번 기본 스위트: **158개 실행, 156개 통과, 실제 모델 opt-in 2개 skip, 실패 0개, 31.495초**. 유효한 기존 Git 경로만 지정했다.
- 위 5개는 정상 테스트에 추가한 회귀 테스트가 아니라 별도로 실행한 합성 경계 점검이다. 테스트 통과 수를 늘린 것으로 보고하지 않는다.
- 이전 M2 실제 CLI·개인 ACP 및 Desktop/브라우저 증거는 [M2 기록](M2_PROGRESS.md)에 있다. 이번 점검에서는 유료 모델과 GUI E2E를 다시 실행하지 않았다.
- 기존 합성 가설·결정·충돌 테스트는 FakeModel이 정답 패치를 내는 Core 테스트다. 실제 모델 테스트의 키워드·카테고리 확인과 제한된 브라우저 사례만으로 누락·허위 주장률을 보장할 수 없다.
- 10+ 활성 세션, 장시간 실행, 사내 운영 정책, 실제 개인 작업에서 재질문 감소는 여전히 미검증이다.

## 5. 갭으로 오해하면 안 되는 의도된 제한

- PR/티켓 외부 상태 unknown: API로 확인하지 않은 값을 사실로 승격하지 않기 위한 계약이다. 외부 API는 M2 필수가 아니다.
- 전체 대화 시간순 복원 미완성: M2 선행 조건에서 명시적으로 제외됐다.
- 자동 태스크 연결·세션 제어·강제 구조 보고·LLM 제공자 확대가 없음: 합의한 범위와 불변식이다.
- 인간 영역과 기계 영역 분리, 구조 변경 승인: 합의된 보호 정책이다. 자동 영역의 자유 섹션 연결 부족과 분리 정책 자체를 혼동하지 않는다.
- 큰 이벤트·미지원 형식에서 실패: 조용한 절단이나 추측보다 안전한 현재 정책이다. 다만 사용 가능한 재개 경로는 별도로 필요하다.

## 6. 수정 우선순위

1. G1의 명시적 의미 공백/재개 정책, G2 혼합 출처 상태 변경 방어, G3 계약 변경 시 신선도 무효화. 정상 경로 외의 추적 신뢰성을 먼저 고친다.
2. G4의 보류 변경 처리와 사용자 status 교정을 연결한다. 각 수정에는 재현 사례의 회귀 테스트를 추가한다.
3. 실제 모델에 라벨된 반복·반박·다중 태스크·범위 변경 사례를 적용해 G5, 누락률, 과잉 주장률, 유용한 갱신당 토큰을 측정한다. 관련 문맥 선택과 예산을 조정한다.
4. 정확도·비용 검증 뒤 opt-in 자동 분석 스케줄을 붙인다. 필요 시 자동 항목과 태스크 고유 섹션의 연결을 제한된 범위로 추가한다.
5. 개인 프로젝트 dogfood와 10+ 활성 세션 부하 검증, 승인된 사내 ACP 검증으로 제품 완료 기준을 확인한다.

새 아키텍처나 UI 리디자인이 필요한 상태라는 뜻은 아니다. 기존 구조 위에서 복구·무효화·적용 조건·기능 연결과 품질 평가를 보강하는 것이 우선이다.
